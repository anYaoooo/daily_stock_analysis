# BTC 交易助手路线图

本文记录项目从 BTC 分析工具走向可验证交易助手的下一步计划。目标不是让系统承诺盈利，而是让每一次分析都更可执行、可回测、可复盘，并逐步形成有纪律的交易闭环。

## 核心定位

系统应优先成为交易助手，而不是预测神谕：

- 观察助手：稳定聚合 BTC 价格、K 线、波动、新闻、宏观驱动和市场状态。
- 决策助手：每次分析输出清晰的多空计划、入场条件、止损、止盈、失效条件和风险收益比。
- 纪律助手：通过回测、追踪和风险控制，减少冲动交易和无计划交易。
- 复盘助手：让历史报告接受市场检验，用数据回答哪些信号有效、哪些信号应该降权。

## 下一阶段计划

### 1. 收敛 BTC-only 用户入口

目标：对用户可见的入口、文案和交互都围绕 BTC 展开，减少股票时代遗留心智。

- CLI 默认分析 BTC，旧 `--stocks` 仅作为兼容入口。
- Web 首页固定围绕 BTC 行情、分析、历史和回测组织。
- API 增加 BTC 语义入口，旧股票命名接口逐步标记为 legacy。
- 文档、Bot 命令、通知文案统一使用 BTC / 标的 / 交易计划语义。

验收标准：

- 新用户不需要理解股票列表、自选股或市场选择就能完成 BTC 分析。
- 非 BTC 输入被明确拒绝或规范为 BTC 别名。
- 股票大盘复盘、股票筛选、股票索引刷新不再出现在默认操作路径中。

### 2. 固化 BTC 交易计划结构

目标：减少 LLM 自由发挥，让每份报告都产出可机器解析的交易计划。

每个计划至少包含：

- `plan_type`：日线多单、日线空单、小时线日内计划等。
- `direction`：long / short / neutral。
- `entry_zone`：入场区间或触发价。
- `stop_loss`：止损价。
- `take_profit`：分批止盈或目标区间。
- `invalid_condition`：失效条件。
- `risk_reward`：风险收益比。
- `position_hint`：仓位建议或风险预算。
- `confidence`：置信度和原因。
- `no_trade_reason`：观望时必须给出原因。

验收标准：

- 回测服务不依赖自然语言猜测关键价位。
- 报告展示层能直接渲染结构化计划。
- 缺失关键字段时报告或任务状态能明确提示质量问题。

### 3. 基于历史分析记录的一键与批量回测

目标：让回测页直接展示历史分析记录，并支持按记录选择回测，而不是要求用户理解底层回测候选和参数。

计划：

- 回测页新增“历史分析记录”列表，展示每一次 BTC 分析报告。
- 每条记录提供单独“回测”按钮，可直接回测该报告中的多单、空单和小时线计划。
- 列表支持复选框选择多条记录并批量回测。
- 列表支持全选当前筛选结果并批量回测。
- 列表支持选择多条或全选后批量删除。
- 回测请求自动携带 `analysis_history_id`、`analysis_mode` 和计划类型，不要求用户手动找记录或填参数。
- 回测完成后在记录行和详情区域展示摘要。
- 已回测的报告在历史分析记录中显示验证状态。

回测摘要至少展示：

- 是否触发入场。
- 入场时间和入场价。
- 最大浮盈、最大浮亏。
- 止盈、止损、失效或未触发状态。
- 净收益率、净 PnL、R 倍数。
- 手续费、滑点和低样本置信标记。

验收标准：

- 用户在回测页即可完成“选择历史分析记录 -> 单条/批量回测 -> 查看结果”的闭环。
- 回测按钮有明确 loading、成功、失败和无可回测计划状态。
- 多选、全选、批量回测和批量删除都有明确确认、进度和结果反馈。
- 重复回测不会产生难以解释的重复记录。

### 4. 优化回测体验与报告关联

目标：把回测从“数据表”变成复盘工具。

- 报告页显示计划级回测卡片。
- 回测页历史分析记录列表显示回测状态：盈利、亏损、未触发、样本不足、待回测。
- 回测页支持按分析模式、方向、计划类型、结果状态筛选。
- 单条回测结果能跳回原始报告。
- 汇总指标区分日线主计划和小时线日内计划。
- 删除历史分析记录前明确提示会影响对应报告、回测入口和可追溯性。

验收标准：

- 用户能快速找到过去有效和无效的信号类型。
- 回测页以历史分析记录为主对象，不再要求用户理解底层表结构。
- 原始分析、交易计划、回测结果之间可以双向跳转。

### 5. 基于现有 BTC 指标的验证闭环

目标：先验证项目已经具备的 BTC 专项指标，而不是急着堆叠更多外部数据。系统应能回答“哪些指标组合真的提高了交易计划质量”，而不是只展示单次报告是否盈利。

当前已具备的 BTC 指标上下文包括：

- Price Action：`breakout`、`breakdown`、`liquidity_sweep_high`、`liquidity_sweep_low`、`bullish_push`、`bearish_push`、`range`。
- Fibonacci：近端 swing high / swing low 与 38.2%、50%、61.8% 回撤位。
- Volume：最新成交量、均量、量比和高/低/正常确认。
- VWAP：rolling 20 VWAP 与价格相对位置。
- EMA：EMA20、EMA50 和 bullish / bearish / mixed 结构。
- Volatility：ATR14、ATR14% 和止损噪音提示。
- 多周期：日线偏向、小时线偏向、`aligned_long`、`aligned_short`、`countertrend_long`、`countertrend_short`、`wait_for_*` 等对齐状态。
- 事件：急跌、扫低、假跌破反弹候选、跌破延续和对应确认价/失效价。

计划：

- 在每个 `daily_long`、`daily_short`、`intraday` 计划生成或回测时，保存当时的低敏指标快照标签。
- 指标快照只保存结构化摘要，不保存无法稳定回放的大段 prompt 或新闻原文。
- 回测汇总按 `plan_type`、`direction`、`price_action.state`、`ema.structure`、`vwap.price_position`、`volume.confirmation`、`intraday.alignment` 和 `event.type` 分组。
- 对每个分组展示样本数、触发率、胜率、平均净收益、最大回撤、平均 R 倍数和低样本置信提示。
- 在报告页和回测页标记“历史表现较弱”的计划类型或指标组合，用于后续风控降权。
- 先完成现有指标的验证闭环，再评估是否接入 funding rate、open interest、ETF 流入和宏观流动性指标。

验收标准：

- 用户能看到“某类 BTC 计划为什么历史上有效或无效”，而不是只看到单笔盈亏。
- 系统能区分顺日线机会、逆日线短线机会、急跌反弹机会和突破追随机会的历史表现。
- 低样本分组必须明确提示，不允许用少量盈利样本提高仓位建议。
- 指标标签能追溯到原始分析记录和计划，但不破坏旧回测结果兼容。

### 6. 补强风险控制层

目标：系统不仅给机会，也要会拦住不该做的交易。

- 单笔最大风险预算。
- 最大杠杆限制。
- 连续亏损冷却。
- 日内最大亏损保护。
- 波动异常时自动降仓或只允许观望建议。
- 回测表现低于阈值的计划类型自动降权。
- 回测表现低于阈值的指标组合自动降权，例如逆日线短线计划、低量突破、VWAP 下方追多或急跌未确认抄底。

验收标准：

- 系统能明确输出“为什么现在不交易”。
- 风险控制规则独立于 LLM 文案执行。
- 交易接口默认 dry-run，不因分析结论自动实盘下单。

### 7. BTC 衍生品与宏观数据扩展

目标：在现有技术指标闭环被验证后，再补充 BTC 特有的杠杆、资金和宏观流动性信息，避免指标堆叠但无法复盘。

优先级：

1. funding rate：识别多空拥挤和追涨追空风险。
2. open interest：识别杠杆扩张、挤压和去杠杆风险。
3. ETF 净流入/净流出：识别现货需求变化。
4. DXY、美债收益率、纳指和黄金：给出宏观风险偏好摘要。
5. 恐惧贪婪指数或稳定币流动性：作为辅助情绪/流动性标签。

验收标准：

- 新数据先作为低敏指标标签和报告上下文，不直接触发实盘交易。
- funding/OI 等数据必须进入回测分组，验证后才能用于风控降权或仓位调整。
- 数据源失败时要明确标记缺失或降级，不把缺失数据误读为中性信号。

### 8. 真实交易接口灰度

目标：只有在回测和小资金验证足够稳定后，才逐步接近真实交易。

- 默认保持 dry-run。
- 先支持手动确认下单。
- 再支持受风险控制约束的半自动执行。
- 所有真实交易前必须保存计划、风控快照和用户确认记录。

验收标准：

- 没有明确确认时，系统不能执行真实下单。
- 实盘行为可追溯到分析报告、计划和风控判断。
- 回滚到纯分析模式只需关闭交易开关。

## 下周优先级

建议下周优先完成前三项：

1. 完成回测页分析模式、方向、计划类型、结果状态筛选。
2. 为历史 BTC 计划补充指标快照标签，先覆盖 Price Action、VWAP、EMA、Volume、ATR、多周期对齐和事件类型。

## 风险与边界

- 回测不能证明未来盈利，只能发现历史上更可靠或更不可靠的计划类型。
- LLM 输出必须被结构化校验约束，不能直接作为交易执行依据。
- 手续费、滑点、资金费率和 K 线粒度会显著影响回测可信度。
- 指标分组只能说明历史样本表现，不能自动推导未来胜率；样本不足时必须降权展示。
- funding/OI 已作为低敏上下文和回测标签接入；后续 ETF/宏观数据仍应通过配置开关和缺失标记控制，避免新增数据源扩大复杂度但无法证明价值。
- 没有足够样本前，不应因为少数盈利样本提高仓位。
- 真实交易功能必须默认关闭，并保留清晰回滚路径。

## 回滚方式

- BTC-only 入口调整可通过保留 legacy API 和旧 CLI 参数兼容回滚。
- 结构化计划 schema 可先以新增字段方式落库，避免破坏旧报告。
- 一键回测入口可通过前端 feature flag 或隐藏按钮回滚。
- 指标快照标签和分组汇总应以新增字段或派生表实现；回滚时保留旧回测结果读取路径。
- funding/OI/宏观数据源应通过配置开关关闭，并在关闭后不影响现有 BTC 技术分析和回测。
- 风控和真实交易相关能力必须可通过环境变量关闭。
