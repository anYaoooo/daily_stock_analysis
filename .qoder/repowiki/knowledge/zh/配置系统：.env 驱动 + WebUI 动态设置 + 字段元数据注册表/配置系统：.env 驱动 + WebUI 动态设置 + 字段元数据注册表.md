## 1. 使用的系统与架构
- 持久化载体：`.env` 文件（dotenv 格式），通过 `src/core/config_manager.py` 的 `ConfigManager` 以原子写入（先写 `.tmp` 再 `os.replace`，失败回退到原地重写）方式读写。
- 运行时加载：`src/config.py` 中的 `setup_env()` 在应用启动时调用 `load_dotenv(dotenv_path=..., override=False)`，默认从 `src/.env` 或 `ENV_FILE` 环境变量指定的路径加载；支持 `override=True` 用于热重载覆盖现有进程环境。
- 单例配置对象：`src/config.py` 中的 `Config` dataclass 作为全局配置单例，所有业务模块通过导入该模块获取类型安全的配置值。
- Web 动态设置：`src/services/system_config_service.py` 暴露完整的 REST API（`/api/v1/config/*`），提供读取、验证、更新、导入/导出、LLM 通道测试与模型发现、通知通道测试等功能，前端通过 React hooks 渲染动态表单。
- 字段元数据注册表：`src/core/config_registry.py` 集中定义每个配置项的标题、描述、分类、数据类型、UI 控件、是否敏感、默认值、校验规则、帮助链接等，驱动 Web UI 动态生成设置页面。
- 配置文件来源优先级：进程环境变量 > `.env` 中保存的值 > 注册表默认值。Web 设置更新仅修改 `.env` 文件，并通过 `reload_now` 参数决定是否立即 `setup_env(override=True)` 重新加载。

## 2. 核心文件与包
- `src/config.py` — 全局 Config 单例、环境变量解析工具、LLM 通道协议归一化、温度/模型路由逻辑等。
- `src/core/config_manager.py` — `.env` 文件的原子读写、版本哈希、更新时间戳、敏感键掩码。
- `src/core/config_registry.py` — 配置字段元数据注册表（SCHEMA_VERSION、分类定义、WEB_SETTINGS_HIDDEN_FROM_UI、_FIELD_DEFINITIONS）。
- `src/services/system_config_service.py` — SystemConfigService 服务层，封装配置读取/验证/更新、LLM/通知通道测试、首次运行检查、导入导出等。
- `api/v1/endpoints/system_config.py` — FastAPI 路由，将 Service 方法暴露为 HTTP 接口，包含鉴权守卫（非桌面模式需 admin session）。
- `docs/examples/litellm_config.example.yaml` — LiteLLM 原生 YAML 配置示例，可作为 LITELLM_CONFIG 指向的高级路由配置。

## 3. 架构与设计决策
- **单一事实源**：`.env` 是唯一持久化存储，所有配置变更最终落盘到该文件，避免多源不一致。
- **原子写入与乐观锁**：`ConfigManager.apply_updates` 使用 `config_version` 进行冲突检测，并发更新时通过版本号防止覆盖。
- **敏感信息保护**：`_SERVER_MASKED_CONFIG_KEYS`（如 `LLM_USAGE_HMAC_SECRET`）在服务端响应中统一替换为 mask_token；`is_sensitive` 标记控制前端密码输入框。
- **分层配置来源**：
  - 进程环境变量（Docker env_file、CI 注入）作为只读显示回退，不覆盖 `.env` 保存值。
  - `.env` 保存值作为主配置源。
  - 注册表默认值作为未设置时的兜底。
- **LLM 配置三轨并行**：
  - 简单模式：`LITELLM_MODEL` + `*_API_KEY` 传统键。
  - 渠道模式：`LLM_CHANNELS` + `LLM_<CHANNEL>_BASE_URL/API_KEY/MODELS` 动态扩展。
  - 专家模式：`LITELLM_CONFIG` 指向标准 litellm_config.yaml，优先级最高。
- **Web 设置与运行时隔离**：Docker 注入的环境变量仅用于显示，不会通过 WebUI 写回 `.env`，避免容器配置被覆盖。

## 4. 约定与约束
- **环境变量命名规范**：全大写蛇形命名，如 `LITELLM_MODEL`、`OPENAI_API_KEY`、`ENABLE_REALTIME_QUOTE` 等，由 `_FIELD_DEFINITIONS` 严格枚举。
- **布尔值解析**：`parse_env_bool` 统一处理 `0/false/no/off` 为 false，其余为 true。
- **数值范围校验**：整数/浮点数解析器支持 minimum/maximum 边界钳制并记录警告日志。
- **敏感键掩码**：服务端响应的敏感字段值会被替换为 `mask_token`，客户端需根据 `raw_value_exists` 和 `is_masked` 判断真实值是否存在。
- **配置版本冲突**：更新时必须携带当前 `config_version`，否则返回 409 Conflict。
- **WebUI 隐藏字段**：`WEB_SETTINGS_HIDDEN_FROM_UI` 列表中的键（如数据库连接、代理、加密货币交易凭据等）不在 Web 设置界面显示，只能通过环境变量或 API 直接操作。
- **LLM 通道协议推断**：`resolve_llm_channel_protocol` 支持从 model 前缀、channel 名称、base_url 自动推断 provider，本地地址默认 openai 协议。
- **首次运行检查**：`get_setup_status` 提供 LLM、Agent、股票列表、通知、存储等关键配置的完整性检查，指导用户完成初始设置。
- **安全访问控制**：非桌面模式下，导出/导入 `.env` 需要启用认证且具备有效 admin session，否则返回 401/403。
