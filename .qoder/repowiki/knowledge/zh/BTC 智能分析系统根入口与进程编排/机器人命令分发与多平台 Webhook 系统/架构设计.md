模块以三层解耦架构组织：
- 入口层 `handler.py` 提供 `handle_webhook` / `handle_webhook_async` 两个统一入口，按 `platform_name` 从 `ALL_PLATFORMS` 缓存中获取对应平台适配器（`platforms/`），由适配器把原始 HTTP 请求转换为统一的 `BotMessage`。
- 核心层 `dispatcher.py` 的 `CommandDispatcher` 维护命令注册表、别名、管理员白名单和基于滑动窗口的 `RateLimiter`；`dispatch`/`dispatch_async` 先做频率限制与参数校验，再调用命令的 `execute`/`execute_async`，并在非命令消息上走 LLM 意图识别（`_try_nl_routing`）回落到 `/chat` 或 `/ask`。
- 命令与平台实现分别位于 `commands/` 和 `platforms/`，两者都依赖 `models.py` 中的 `BotMessage`、`BotResponse`、`WebhookResponse` 三个数据类作为跨层契约。
- 全局单例通过 `get_dispatcher()` 懒初始化并自动注册 `bot.commands.ALL_COMMANDS` 中的所有命令类；平台实例通过 `_platform_instances` 字典缓存，避免重复构造。
- 自然语言路由通过 `src.agent.llm_adapter.LLMToolAdapter` 调用 LLM 提取 intent/codes/strategy，受 `config.agent_nl_routing` 与 `config.agent_mode` 双重开关控制，且仅在私聊或被 @ 时生效。
