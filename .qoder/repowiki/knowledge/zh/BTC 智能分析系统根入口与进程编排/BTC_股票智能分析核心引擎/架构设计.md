src/ 按职责划分为 agent（LLM Agent 及技能/策略/工具路由）、core（回测引擎、交易日历、市场策略）、data（股票映射与指数加载）、llm（LiteLLM 统一调用封装）、notification_sender（多渠道推送实现）、repositories（ORM 访问抽象）、schemas（Pydantic/TypedDict 数据契约）、services（用例编排层）与 utils（通用工具），并由顶层文件提供启动期能力：
- 配置契约：src/config.py 的 Config dataclass 单例通过 parse_env_* 从 .env/LiteLLM YAML 解析并校验所有配置项，被 services、agent、core 等子包通过 get_config() 读取，形成全局事实源。
- 持久化契约：src/storage.py 基于 SQLAlchemy declarative_base 集中定义 stock_daily、analysis_history、backtest_results、crypto_backtest_*、portfolio_*、conversation_*、agent_provider_turns、llm_usage、alert_* 等模型，并通过 schema_migrations 表管理版本迁移；services/repositories 层统一经此访问数据库，避免直接耦合。
- 调度契约：src/scheduler.py 封装 schedule 库并提供 Scheduler + GracefulShutdown，支持 daily/hourly 模式与后台任务线程池，被 services/task_service、btc_volatility_monitor 等周期性任务复用。
- 认证契约：src/auth.py 提供 PBKDF2 密码哈希、HMAC session、IP 级暴力破解限流，供 webui_frontend 及 CLI reset_password 使用。
- 通知契约：各 notification_sender/* 实现 notification_contracts 定义的统一接口，由 src/notification_routing 按 channel 名称分发，services 层仅依赖抽象而非具体通道。
- 编排流向：services/* 作为用例层把 agent、core、repositories、notification_sender 串联成 run_flow / analysis_service 等用例；agent/* 通过 src/llm/* 统一调用 LiteLLM，通过 src/notification.py 推送结果，共享 src/enums.ReportType 等枚举；core/* 提供 backtest_engine、market_strategy、trading_calendar 等业务内核，对外暴露纯函数或类接口供 services 调用。
- 当前改进方向：将 BTC 执行契约校验从"失败即降级观望"改为"只做标注"，通过 prompt 约束入场价贴近现价并解冻僵化的 execution_contract 模板以提升计划触发率，同时用回放工具定标后在本地 .env 启用已实现的监控自适应能力。
