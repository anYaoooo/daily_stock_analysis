## 简介
本文件为 daily_stock_analysis 项目的开源贡献规范与流程说明，覆盖 Issue 提交流程、Pull Request 创建规范、代码审查流程、版本发布流程、变更日志维护、文档更新要求、社区参与指南、行为准则、许可证说明、新功能开发流程、Bug 修复流程、文档贡献流程以及 CI/CD 流水线的作用与配置方法。目标是让新贡献者快速上手，同时保证提交质量与发布稳定性。

## 项目结构
仓库采用多语言、多模块组织：Python 后端（API、Agent、数据源、通知等）、Web 前端（React/Vite）、桌面端（Electron）、Bot 平台集成、测试与脚本、文档与 Docker 编排等。贡献相关的关键位置如下：
- .github：GitHub Actions、PR 模板、Release 工作流、CI 依赖清单
- scripts：构建与 CI Gate 脚本
- docker：容器化与编排
- docs：贡献指南、部署、FAQ、示例配置等
- pyproject.toml / requirements.txt / setup.cfg：Python 依赖与工具配置
- SKILL.md 与 .agents/skills/*：AI 辅助技能定义（Issue 分析、PR 分析、修复）

```mermaid

participant Release as "发布工作流"
participant Artifacts as "制品/变更日志"
Dev->>GH : 推送分支并创建PR

Build-->>CI : 构建产物

Note over CI,GH : 审查通过后合并
GH->>Release : 合并触发release.yml
Release->>Artifacts : 生成制品与变更日志
Artifacts-->>Dev : 发布结果通知
```

## 详细组件分析

### Issue 提交流程
- 使用 GitHub Issues 模板描述问题背景、复现步骤、期望行为、实际行为与环境信息
- 提供最小可复现代码或请求样例，标注影响范围与优先级
- 若涉及安全或敏感信息，请走私有渠道沟通
- 标签与分类由维护者根据内容设置

```mermaid
flowchart TD
Start(["开始"]) --> Create["创建Issue"]
Create --> FillTemplate["填写模板信息"]
FillTemplate --> AttachEvidence["附加证据/日志/截图"]
AttachEvidence --> Submit["提交Issue"]
Submit --> Triage{"维护者分诊"}
Triage --> |确认| Assign["分配负责人/标签"]
Triage --> |重复/无效| Close["关闭或转存"]
Assign --> Fix["修复/讨论"]
Fix --> Verify["验证与回归测试"]
Verify --> Done(["完成"])
```

### Pull Request 创建规范
- 基于功能分支开发，保持提交原子性与语义化
- PR 标题遵循“类型(模块): 简述”的约定
- 描述中说明动机、变更点、影响面、测试覆盖与回滚方案
- 关联相关 Issue，必要时附上截图/日志
- 确保通过所有 CI 检查后再请求审查

```mermaid
flowchart TD
Start(["开始"]) --> Branch["创建功能分支"]
Branch --> Commit["提交代码(语义化)"]
Commit --> Test["本地测试通过"]
Test --> Push["推送分支并创建PR"]
Push --> Review["代码审查"]
Review --> Feedback{"是否需要修改?"}
Feedback --> |是| Update["更新PR并补充测试"]
Feedback --> |否| Approve["获得批准"]
Approve --> Merge["合并至主分支"]
Merge --> End(["结束"])
```

### 代码审查流程
- 至少一名维护者审查，关注正确性、可读性、性能与安全
- 使用评论与建议进行迭代，避免破坏性变更
- 对复杂逻辑增加单元测试或集成测试
- 审查通过后由维护者合并

```mermaid

Reviewer->>Dev : 提出修改建议
Dev->>Reviewer : 更新PR并回复
Reviewer-->>Dev : 批准合并
```
